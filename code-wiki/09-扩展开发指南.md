# 扩展开发指南

本文面向需要在本仓库内新增或修改前端功能的开发者，内容包括插件（`JupyterFrontEndPlugin`）的解剖、由简到繁的真实范例、设置 schema 机制、从源码到页面的装配链路，以及"新增一个页面"的完整流程与排障方法。前端包与页面装配的背景见 [04-前端模块详解](04-前端模块详解.md) 与 [02-整体架构](02-整体架构.md)。

## 插件解剖

本仓库全部前端功能以 JupyterLab 约定的插件对象组织，TypeScript 类型为 `JupyterFrontEndPlugin<T>`：

```typescript
const myPlugin: JupyterFrontEndPlugin<void> = {
  id: '@jupyter-notebook/包名:插件名',   // 全局唯一，也是设置系统的主键
  description: '插件用途描述',
  autoStart: true,                       // 应用启动即激活（本仓库全部如此）
  requires: [INotebookShell, ITranslator],  // 必需服务（Token），缺失则插件不激活
  optional: [ICommandPalette],              // 可选服务，activate 中以 `| null` 接收
  provides: INotebookPathOpener,            // 本插件对外提供的服务（可省略）
  activate: (app, shell, translator, palette) => {
    // 依赖注入完成后被调用一次；app.commands / app.shell / app.serviceManager 都可用
  },
};
```

要点：

- `requires` 中的 Token 按 `@lumino/coreutils` 的 `Token<T>` 解析，形成插件的依赖图；`PluginRegistry` 负责拓扑激活。
- `optional` 让插件在服务缺失时降级运行——本仓库大量使用它兼容"JupyterLab 里运行"（拿不到 `INotebookShell`）与"Notebook 里运行"两种环境，[lab-extension](../packages/lab-extension/src/index.ts) 的界面切换器就是典型。
- `activate` 的返回值即 `provides` 声明的服务实例。

## 三个真实范例（由简到繁）

以下范例直接取自仓库源码，可对照阅读。

### 范例一：最小部件插件（menu-spacer）

[application-extension/src/index.ts](../packages/application-extension/src/index.ts) 的 `menuSpacer`——向菜单区塞一个占位部件：

```typescript
const menuSpacer: JupyterFrontEndPlugin<void> = {
  id: '@jupyter-notebook/application-extension:menu-spacer',
  description: 'A plugin to provide a spacer at rank 900 in the menu area.',
  autoStart: true,
  activate: (app: JupyterFrontEnd) => {
    const menu = new Widget();
    menu.id = DOMUtils.createDomID();
    menu.addClass('jp-NotebookSpacer');
    app.shell.add(menu, 'menu', { rank: 900 });   // rank 越小越靠前，默认 900
  },
};
```

这是"往 shell 某区域放一个部件"的最短路径。注意 `app.shell` 的实际类型是 [NotebookShell](05-关键类与函数.md#notebookshell)，六区语义与 JupyterLab 的 `ILabShell` 不同。

### 范例二：提供服务（path-opener）

同文件中的 `pathOpener` 演示 `provides`——把默认路径打开器注册为 `INotebookPathOpener` 服务，供 docmanager 等消费：

```typescript
const pathOpener: JupyterFrontEndPlugin<INotebookPathOpener> = {
  id: '@jupyter-notebook/application-extension:path-opener',
  autoStart: true,
  provides: INotebookPathOpener,
  activate: () => defaultNotebookPathOpener,
};
```

要覆盖打开行为（例如改为当前标签内导航），下游可再写一个 `provides` 同一 Token 的插件并禁用原插件（见文末"禁用插件"）。

### 范例三：设置 + 命令 + 调色板（full-width-notebook）

[notebook-extension/src/index.ts](../packages/notebook-extension/src/index.ts) 的 `fullWidthNotebook` 是本仓库最典型的"可配置命令"模式：

- 依赖 `INotebookTracker`（追踪打开的笔记本），可选 `ISettingRegistry`、`ICommandPalette`、`ITranslator`；
- 读取设置的固定四步：

```typescript
settingRegistry.load(fullWidthNotebook.id)          // 1. 以插件 id 为键加载
  .then(...)                                         //    与 app.restored 汇合后
  // 2. settings.get('fullWidthNotebook').composite 读取用户值（含默认值回退）
  // 3. settings.changed.connect(...) 监听运行期修改
  // 4. 命令执行时反向 notebookSettings.set(key, value) 持久化
```

- 命令经 `app.commands.addCommand` 注册（`isEnabled`/`isToggled` 控制可用与勾选态），并加入命令调色板。

配套 schema [schema/full-width-notebook.json](../packages/notebook-extension/schema/full-width-notebook.json) 声明 `fullWidthNotebook` 布尔属性，构建时安装到 `share/jupyter/lab/schemas/@jupyter-notebook/notebook-extension/`。

### 进阶模式速览

| 需求 | 参考实现 |
| --- | --- |
| 声明式加菜单项（不改代码） | 在插件 schema 中写 `jupyter.lab.menus`，如 [schema/zen.json](../packages/application-extension/schema/zen.json) 把 `application:toggle-zen` 注入 View 菜单 |
| 工具栏部件 | 经 `IToolbarWidgetRegistry.addFactory('TopBar'|'Notebook', 名称, factory)` 注册，如 title 插件的 `widgetTitle` |
| 修改 URL（前端路由） | 用 `IRouter.navigate`，title 插件重命名后同步地址栏即是 |
| 按页面裁剪行为 | 读 `PageConfig.getOption('notebookPage')` 分支，如 menus 插件在 tree/console/terminal 页销毁 Edit/Kernel/Run 菜单 |
| 服务端数据 | 走 `app.serviceManager`（contents/kernels/sessions/terminals/settings），不要自行 fetch |

## 从源码到页面：插件装配链路

新插件写完后，让它出现在页面上需要经过五站：

1. **包内导出**：在包的 `src/index.ts` 末尾加入插件数组并 `export default`（见 [notebook-extension/src/index.ts](../packages/notebook-extension/src/index.ts) 的 `const plugins: JupyterFrontEndPlugin<any>[] = [...]` 模式）。
2. **页面白名单**：在 [app/package.json](../app/package.json) 的 `jupyterlab.plugins` 中，把插件 id（或整个包）加入目标页面——`"/"` 键对所有页面生效，`"/notebooks"` 等仅对应页面生效；数组形式表示"从该包只挑这些 id"。
3. **编译**：`jlpm build`（metapackage 级联 tsc 编译各包 `lib/`）。
4. **打包**：rspack 经 Handlebars 把白名单展开成 `require(...)` 写入 bundle（详见 [07-构建与运行](07-构建与运行.md#构建管线原理)）。
5. **运行时装配**：[index.template.js](../app/index.template.js) 的 `main()` 按当前页 `notebookPage` 选择分支注册插件。

新增包则还需：加入根 workspace（`packages/*` 自动包含）、加入 [_metapackage](../packages/_metapackage/package.json) 依赖、（若要进默认页面）加入 [app/package.json](../app/package.json) dependencies 与 `jupyterlab.plugins`。

## 新增一个页面（全流程）

目标：新增 `{base_url}/mypage`，使用独立模板与专属插件集。涉及前端模板、构建配置、（可选）后端路由三处改动。

第 1 步，创建页面模板。复制 [app/templates/tree_template.html](../app/templates/tree_template.html) 为 `app/templates/mypage_template.html`，把 Jinja2 中的页面哨兵改为新页名：

```jinja
{% set _ = page_config_full.update(notebookPage='mypage') %}
```

模板保留了三件关键事务：`<script id="jupyter-config-data">` 注入 page_config、`wsUrl/baseUrl` 合并、URL 中 token 的清除脚本。

第 2 步，登记模板输出。在 [app/rspack.config.js](../app/rspack.config.js) 的 htmlPlugins 遍历数组 `['consoles', 'edit', 'error', 'notebooks', 'terminals', 'tree']` 中加入 `'mypage'`。构建时 HtmlWebpackPlugin 会据此生成 `notebook/templates/mypage.html`。

第 3 步，声明页面插件。在 [app/package.json](../app/package.json) 的 `jupyterlab.plugins` 中新增 `"/mypage"` 键（`"/"` 的基础插件自动包含）：

```json
"/mypage": {
  "@jupyter-notebook/tree-extension": false,
  "你的包名": ["你的插件id"]
}
```

第 4 步（仅当页面需要路径语义时），添加后端处理器。在 [notebook/app.py](../notebook/app.py) 中仿照 `TreeHandler` 编写 `MyPageHandler(NotebookBaseHandler)` 渲染 `mypage.html`，并在 `JupyterNotebookApp.initialize_handlers` 中注册：

```python
self.handlers.append(("/mypage(.*)", MyPageHandler))
```

第 5 步，重建并验证：

```bash
jlpm build        # 或已开启 jlpm watch
# 若改了 notebook/app.py，重启 jupyter notebook
```

预期结果：浏览器访问 `{base_url}/mypage` 返回 200，页面源码中 `jupyter-config-data` 含 `"notebookPage": "mypage"`，bundle 仅加载 `"/"` 与 `"/mypage"` 白名单中的插件。

### 排障

| 现象 | 原因与处理 |
| --- | --- |
| 访问 `/mypage` 404 | 后端 handler 未注册，或改了 `app.py` 后未重启 Python 进程（模板目录在启动时确定） |
| 页面空白、控制台报插件找不到 | `"/mypage"` 键拼写与模板中 `notebookPage` 值不一致（前端以 `/${notebookPage}` 匹配）；或插件未加入对应页面白名单 |
| 设置编辑器里看不到新 schema | 未执行 `jlpm develop`（schema 未链接到 app 目录），或 schema 未随包声明 `schemaDir` |
| 菜单/工具栏不出现 | schema 的 `jupyter.lab.menus`/toolbar 注册依赖对应页面已加载 `@jupyterlab/mainmenu-extension` 等基础插件（`"/"` 键默认已含） |

## 调试技巧

- 暴露应用实例：`jupyter notebook --expose-app-in-browser` 后，浏览器控制台可用 `window.jupyterapp`（`.commands`、`.shell` 均可交互，例如 `window.jupyterapp.commands.execute('application:toggle-zen')`）。
- 禁用插件：page_config 的 `disabledExtensions` 支持按插件 id 或扩展包名禁用（[index.template.js](../app/index.template.js) 的 `isExtensionDisabled`/`PageConfig.Extension.isDisabled`），可在服务器配置中注入 page_config 选项做对照实验。
- 增量迭代：`jlpm watch` + 浏览器硬刷新即可看到 TS 改动，无需重启服务器。
- 回归验证：涉及 UI 的改动在 [ui-tests/](../ui-tests/) 中补 Playwright 用例并更新快照（见 [08-测试体系](08-测试体系.md)）。
